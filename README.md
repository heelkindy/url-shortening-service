# URL Shortening Service

A RESTful API for shortening long URLs, built with **Java** and **Spring Boot**. This project is my solution to
the [URL Shortening Service](https://roadmap.sh/projects/url-shortening-service) challenge
from [roadmap.sh](https://roadmap.sh/backend/projects) — the first project in the Intermediate tier.

## Tech Stack

- **Java 21**
- **Spring Boot 3** (Spring Web, Spring Data JPA)
- **MySQL** (running via Docker)
- **Maven**
- **Bean Validation** (Jakarta Validation)

## How Short Codes Are Generated

Short codes are generated by Base62-encoding the auto-incrementing database ID of each URL record (alphabet: `0-9`,
`a-z`, `A-Z`), rather than generating a random string and checking for collisions. This is the same general approach
used by real-world URL shorteners: encoding a sequential ID guarantees uniqueness without needing a collision check or
retry loop, and produces short, compact codes that get only slightly longer as the ID grows.

Per the project spec, this API intentionally has **no authentication or authorization** — the focus is on core CRUD
functionality and access statistics tracking.

## Features

- Create a new short URL from a long URL
- Retrieve the original URL from a short code
- Update the original URL behind an existing short code
- Delete an existing short URL
- Track and retrieve access statistics (number of times a short URL has been resolved)

## Getting Started

### Prerequisites

- JDK 21+
- Maven
- Docker (for running MySQL locally)

### Run the database

```bash
docker compose up -d
```

This starts a MySQL container as defined in `docker-compose.yml`.

### Run the application

```bash
./mvnw spring-boot:run
```

The API will be available at `http://localhost:8080`.

## API Endpoints

| Method   | Endpoint                     | Description                           |
|----------|------------------------------|---------------------------------------|
| `POST`   | `/shorten`                   | Create a new short URL                |
| `GET`    | `/shorten/{shortCode}`       | Retrieve the original URL             |
| `PUT`    | `/shorten/{shortCode}`       | Update the original URL               |
| `DELETE` | `/shorten/{shortCode}`       | Delete a short URL                    |
| `GET`    | `/shorten/{shortCode}/stats` | Get access statistics for a short URL |

## Example Requests

**Create a short URL**

```bash
curl -X POST http://localhost:8080/shorten \
  -H "Content-Type: application/json" \
  -d '{"url": "https://www.example.com/some/long/url"}'
```

Response:

```json
{
  "id": "1",
  "url": "https://www.example.com/some/long/url",
  "shortCode": "1",
  "createdAt": "2026-07-23T12:00:00Z",
  "updatedAt": "2026-07-23T12:00:00Z"
}
```

**Retrieve the original URL**

```bash
curl -i http://localhost:8080/shorten/1
```

**Update a short URL**

```bash
curl -X PUT http://localhost:8080/shorten/1 \
  -H "Content-Type: application/json" \
  -d '{"url": "https://www.example.com/some/updated/url"}'
```

**Get access statistics**

```bash
curl http://localhost:8080/shorten/1/stats
```

## Architecture Notes

- **Two-step save for Base62 encoding**: since the short code depends on the auto-generated ID, the entity is saved once
  to obtain its ID, then updated with the encoded `shortCode` in a second save — the ID isn't known before the first
  insert.
- **Database portability**: entity, repository, and service code is written against JPA/Hibernate abstractions, not
  MySQL-specific syntax — switching the underlying database (as was considered between PostgreSQL, MySQL, and MongoDB
  during planning) mainly involves changing the driver, dialect, and connection configuration.
